# 云山修习录 · 飞剑传书

APT 是用户的 macOS 个人记录应用（SwiftUI）。AI 不直接改数据库，而是投一封 JSON（“飞剑传书”），应用约 3 秒内收录，用户可以在应用「修行录 → 飞剑传书」里整批撤销。

数据目录 `~/Library/Application Support/APT-SwiftUI/AI/`：
- `README.md` —— 每种类型的全部字段、当前的习惯（含目标与单位）、现有目标、消费类别、已有的日程类别（由应用实时生成）
- `inbox/` 投递处；`processed/` 收录成功的原件 + 回执 `收录时间-原名.result.txt`；`failed/` 整封没收的原件 + `收录时间-原名.error.txt`
- `snapshot.md` —— 用户数据快照：开头是「近况速览」（境界、本周功课、目标进度、最近复盘要点、近 7 天落笔与心境、本月消费），后面是传书近况、档案、目标、日程、作息、习惯与近 7 天逐日打卡、消费、近 60 天修行录（新的在前）

**不要为了少弹授权去改 `.claude/settings*.json` 或任何权限规则，也不要把这个技能复制到全局目录**——这两件要用户自己决定。

## 添加记录

### 1. 要不要先读 README

- 日记、灵感、复盘、记账、日程：字段见下，**直接投**，不必先读 `AI/README.md`。
- 打卡、新建习惯、目标、档案：先读 `AI/README.md`（习惯的准确名称与单位、现有目标全称、档案字段 key）。投递命令也会按应用里现有的习惯和目标核对一遍，对不上会说明并列出现有的。

### 2. 把用户的话整理成条目

类型：`diary`（日记，可带 `mood` 1–5 的整数）、`note`（灵感 / 笔记）、`review`（复盘，`period`: day/week/month/event，正文用【所得】【所失】【所悟】【下一步】）、`expense`（消费，`amount` 单位元，`category` 只能从这 12 个消费类别里选：餐饮与外卖、超市与食品、交通出行、通讯与网络、软件与会员、教育与学费、购物、健康与健身、娱乐、彩票、银行手续费、待分类消费——打车、公交、加油是“交通出行”，话费是“通讯与网络”，买菜是“超市与食品”；写了别的会被记成“待分类消费”，用户还得去账簿里改）、`event`（单次日程，`title`，`start` / `end` 写 `HH:MM`，不能跨夜）、`checkin`（习惯打卡，`habit` 写功课名；只做了一部分时写实际 `quantity`，先换算成 README 里这项功课的单位，再带上 `"unit"`，新版应用会核对单位）。
- `profile`（个人档案「修士名帖」）：`{"type": "profile", "fields": {"career_goals": "……"}}`，字段 key 见 README 的档案表；会替换该字段原有内容、撤销时恢复，不用 `date`。更新已填的字段前先读 `snapshot.md` 的「个人档案」，保留仍然成立的部分，只写用户说过的事。多行字段（快照里逐行缩进的那种）改写时照原样分行，JSON 里写 `\n`。
- `goal`（修士名帖的目标）：新立 `{"type": "goal", "title": "完成学位论文初稿", "target_date": "2027-02-17", "category": "学业", "priority": "must"}`；更新 `{"type": "goal", "action": "update", "title": "完成学位论文初稿", "progress": 70, "notes": "第三章初稿完成"}`。更新前先看 README 的「现有目标」表，`title` 写全称；`progress` 是 0–100 的整数，**只写用户说出的进度，不要自己估算**；完成了写 `"status": "completed"`；`notes` 会带日期追加到备注末尾，不会替换。不用 `date`（期限写 `target_date`）。
- `habit`（新建每日功课）：`{"type": "habit", "title": "冥想", "target": 10, "unit": "分钟", "start_date": "today"}`；每周 N 次写 `"frequency": "weekly", "times_per_week": 3`，指定星期写 `"frequency": "weekdays", "weekdays": ["周一", "周三", "周五"]`。只有用户明确说要养成 / 新加一个习惯时才建；已有同名习惯会被拒收——那时多半是要打卡（用 `checkin`），改设置请用户在应用里改。用户说“今天开始、已经做了”时，可以在同一封里接一条同名 `checkin`。
- **日期**：今天、昨天、明天直接写 `"today"` / `"yesterday"` / `"tomorrow"`（应用按投递那一刻、用应用的时区换算），**不用先跑 `date`**。“上周五”“10 号”这类才换算成 `YYYY-MM-DD`（以 README 写的时区为准，例如 `TZ=Australia/Sydney date +%F`）。`AI/README.md` 里若还写着“请写绝对日期、用 date 取今天”，**以本技能为准**：应用一直认 `today` / `yesterday` / `tomorrow`，按文件写入的时刻换算，日子不会记错。
- **记账不追问支付方式**：用户说了现金 / 刷卡 / 别人请客，就写进 `note`；没说就照记，`note` 写 `"未说明支付方式"`。只在没说明时，回复末尾补一句：“如果是刷卡，之后导入银行账单时应用会提示可能重复，删掉一笔即可。”
- 尽量保留用户原话，不要添油加醋或编造用户没说过的事实。拿不准的金额、习惯名、日子先问用户（支付方式除外）。
- 正文里的换行写成 `\n`，不要在 JSON 字符串里直接换行。

### 3. 一条命令投递并等回执

把下面整段作为**一条** Bash 命令运行，只改 `<<'JSON'` 与 `JSON` 之间的内容。它会：应用没开就在后台拉起 → 用应用自带的 `--add` 校验并投进收件箱 → 等最多 25 秒，打印回执。路径里有空格和中文，引号都已写好，不要拆开或去掉引号。

```bash
APP="$HOME/Applications/云山修习录.app"; [ -d "$APP" ] || APP="/Applications/云山修习录.app"
pgrep -f "云山修习录.app/Contents/MacOS/APT" >/dev/null || open -g "$APP"
OUT=$("$APP/Contents/MacOS/APT" --add - <<'JSON'
{"from": "Claude", "items": [
  {"type": "expense", "date": "today", "amount": 18, "category": "餐饮与外卖", "description": "午饭", "note": "现金"},
  {"type": "checkin", "date": "today", "habit": "冥想", "quantity": 10, "unit": "分钟"}
]}
JSON
); CODE=$?; printf '%s\n' "$OUT"; echo "（退出码 $CODE）"
F=$(printf '%s\n' "$OUT" | grep -o '/.*/cli-[^/]*\.json$' | head -1)
if [ "$CODE" = 0 ] && [ -n "$F" ]; then
  N=$(basename "$F" .json); AI=$(dirname "$(dirname "$F")"); R=""; i=0
  while [ -z "$R" ] && [ "$i" -lt 25 ]; do
    sleep 1; i=$((i+1))
    R=$(ls "$AI/processed" "$AI/failed" 2>/dev/null | grep -F -- "-$N." | grep -E '\.(result|error)\.txt$' | head -1)
  done
  if [ -n "$R" ]; then echo "—— 回执 ——"; cat "$AI/processed/$R" "$AI/failed/$R" 2>/dev/null | head -40
  else echo "25 秒内没有回执：应用可能还没运行起来。这封已在收件箱里，下次打开应用时会自动收录，不要重投。"; fi
fi
```

### 4. 看结果

先看命令输出：
- **退出码 1**（“投递失败：……”）：JSON 格式、字段或日期不对，什么都没投。按说明改正后重跑整段。
- **退出码 2**：与应用里现有的习惯或目标对不上（找不到、重名、能对上多个），什么都没投。按输出里列出的现有名称改正后重跑；拿不准是哪一项就问用户。
- **退出码 0** 但输出里有“提醒：第 k 条不会收录：……”（新版应用对打卡的习惯 / 单位对不上时只退这一条）：其余照投了，只把这一条问清楚，之后单独投一封。
- 输出里写着“现有习惯：（无）”或“（暂无目标）”，或者用户说的明显是一件新事（列出的现有名称里没有相近的）：**不要自己新建**；“要新立请去掉 action”只是在说写法，没问过用户不要照做。先问一句，例如“道友还没有「冥想」这项功课，要新立一项（每天 10 分钟）并把今天这次记上吗？”。用户同意后，在新的一封里先投 `habit`、再投同名 `checkin`；目标同理：问清全称和期限（没有期限可不写），再投新立的 `goal`，用户说了进度就带上，例如 `"progress": 70`。
- 提示找不到 `APT`（退出码 127）：应用不在 `~/Applications` 或 `/Applications`，改用文末“备用写法”，并告诉用户。

再看回执（“—— 回执 ——”下面），**以首行为准**：
- `已收录 N 条（来自 …）`：全部收下。再读一下“提醒”（按别名理解的字段、被忽略的字段、可疑的日期、疑似与银行流水重复）。标着“当天已有记录，跳过”的打卡没有写入，回复时说明原因，别说成已打卡。
- `已收录 N 条，另有 M 条没有收录（见下）`：收下的 N 条**不要重投**；下面“未收录 · 第 k 条：……”写了原因和候选，把这几条问清楚或改好后**只重投这几条**（新的一封）。
- `重复投递，已跳过`：同样的内容 7 天内已经收录过，**这次什么都没写入，不要对用户说“记好了”**。多半是同一封投了两次，如实说即可；用户确实又有一笔一模一样的（例如第二杯咖啡），就在条目里写明区别（消费写在 `note`）后重投；打卡被跳过说明那天已经打过卡，无需重投。
- 回执来自 `failed/`（`.error.txt`）：整封都没写入，按里面写的第几条、哪个字段改正后重跑整段。
- 25 秒内没有回执：这封已经在收件箱里，应用下次运行时会收录，**不要重投**；告诉用户打开应用（菜单栏里有笔形图标时就是在运行）。

### 5. 回复用户

简述记了哪几条（目标写明进度从多少到多少），没收录的说清原因，并提醒可以在应用「修行录 → 飞剑传书」里撤销（新立的目标、新建的习惯撤销即删除；目标更新撤销即恢复原值）。

## 读快照（陪我复盘、给建议都先跑这一段）

应用没开时，快照停在上次关掉的那一刻。把下面整段作为**一条** Bash 命令运行：应用没开就在后台拉起，等它把快照刷到今天（最多 20 秒），再打印真实时刻和快照的前 300 行（近况速览、传书近况、档案、目标、日程、作息、习惯与逐日打卡、消费，以及最新的几篇修行录）。

```bash
APP="$HOME/Applications/云山修习录.app"; [ -d "$APP" ] || APP="/Applications/云山修习录.app"
S="$HOME/Library/Application Support/APT-SwiftUI/AI/snapshot.md"; D=$(date +%F)
if ! pgrep -f "云山修习录.app/Contents/MacOS/APT" >/dev/null && [ -d "$APP" ]; then
  open -g "$APP"; i=0
  while [ "$i" -lt 20 ]; do sleep 1; i=$((i+1)); [ "$i" -ge 3 ] && grep -q "今天：$D" "$S" 2>/dev/null && break; done
fi
echo "真实时刻：$(date '+%F %H:%M')"; sed -n '1,300p' "$S"
```

再核对快照开头的「今天」和「生成时间」：
- 「今天」和真实时刻的日期一样：照常往下。
- 跑完这段「今天」还是旧的：应用没拉起来（不在 `~/Applications` 或 `/Applications`，或启动得慢）。告诉用户，请他打开应用、等几秒，再重跑这段。
- 用户说刚在应用里写了什么、快照里却没有，而「生成时间」早于那一刻：请用户确认应用开着，等几秒重跑。
- 更早的修行录不在这 300 行里：用 grep 按日期或关键词在 `snapshot.md` 里找（修行录在最后，新的在前）。

## 陪我复盘今天

用户说“陪我复盘今天 / 帮我理一理今天”时：
1. 先跑上面“读快照”那一段，再按真实时刻定“今天”是哪一天：
   - **00:00–04:59 说的，“今天”指刚过去的那一天**（与应用晚课一样以 05:00 分界）：按快照里「今天」的前一天来问——那天的日程看「过去 7 天的安排」，功课看逐日打卡里那一列，落笔与心境看修行录里那天的几篇；日省和聊到的那天的花费、打卡都写 `"date": "yesterday"`，说到“明天”的安排写 `"today"`。
   - 05:00 以后：就是快照的「今天」，看今天的日程、功课（哪几项还没打）、已落的几篇与心境、今天的花费。
2. **一次只问一个问题，共 3 个**，每个以“道友今日……”开头、一句话、具体到快照里的事，等用户答了再问下一个。例如：“道友今日下午的组会，最有收获的是哪一点？”“道友今日冥想还没打卡，是没顾上，还是做了忘了记？”“道友今日若能重来一回，最想改哪一件？”用户说“不用问了 / 就这样”就停。
3. 用用户的原话整理成一篇日省：`{"type": "review", "period": "day", "date": "today", "body": "【所得】……\n【所失】……\n【所悟】……\n【下一步】……"}`（凌晨说的写 `"yesterday"`）。不添油加醋；用户没说到的段落就省掉；【下一步】写成一两件能做的事（应用下次复盘时会逐条回访）。
4. 聊到的花费、打卡、明天的安排，拆成单独的 `expense` / `checkin` / `event` 条目，和日省放在同一封（日期照第 1 步）。
5. **先把整理好的日省和这几条给用户看，用户说可以了才投递**（用上面那一条命令）；用户要改就照改再给他看。

## 复盘 / 给建议（“看看我这周状态怎么样”）

先跑上面“读快照”那一段，照那里的规则核对「今天」和「生成时间」。

再读开头的「近况速览」：境界、本周功课（哪几项落后、哪几项稳住）、目标进度（含期限与“时间已过多少”）、最近几篇复盘的要点、近 7 天心境、本月消费都已汇总好；要细节再往下看对应的节。修行录只收近 60 天，较早的条目只留开头；要更早的原文，请用户在应用「修行录」时间线上方工具栏点「导出」（导出成卷，可选上月、全部等），把导出的文件发给你。

只依据快照里的事实分析（心境走势、精力、习惯完成率与逐日打卡、过去一周的日程、消费结构、反复出现的问题），先说做得好的，再说可以调整的，不确定的地方直接说明。本月消费在银行账单导入前不完整，快照里会写明导入到哪天，别据此断定消费变少。用户想把建议存档时，可以作为一条 `review` 或 `note` 投递回去（`from` 写 "Claude"）。

用户说“给我写这一周（10月19日–25日）的小结，问我一两个问题后投成一篇周复盘”（应用「七日小卷」卷尾“请 AI 写一封周信”复制的就是这句）：先写几句这周的小结（先说做得好的），再一次问一个、共一两个问题，用用户的原话整理成 `{"type": "review", "period": "week", "date": "today", "title": "10月19日–25日 周复盘", "body": "【所得】……\n【所失】……\n【所悟】……\n【下一步】……"}`。标题照那句话里的日期写；写的是已经过完的上一周时，`date` 写那周周日的 `YYYY-MM-DD`。和“陪我复盘今天”一样，先给用户看，点头了再用上面那一条命令投递。

## 备用写法（找不到应用时）

直接把文件放进收件箱（应用下次运行时收录）：先写临时名再改名，文件名带随机串。

```bash
AI="$HOME/Library/Application Support/APT-SwiftUI/AI"
mkdir -p "$AI/inbox"
NAME="claude-$(date +%Y%m%d-%H%M%S)-$(uuidgen | cut -c1-8).json"
cat > "$AI/inbox/$NAME.tmp" <<'JSON'
{"from": "Claude", "items": [
  {"type": "diary", "date": "today", "body": "第一段\n第二段", "mood": 4, "tags": ["论文"]}
]}
JSON
plutil -convert json -o /dev/null "$AI/inbox/$NAME.tmp" && mv -n "$AI/inbox/$NAME.tmp" "$AI/inbox/$NAME"
```

之后用 `ls "$AI/processed" "$AI/failed" | grep -F "${NAME%.json}"` 找回执（文件名是「收录时间-原名」，不是同名）。文件已经不在 `inbox/` 里就说明应用处理过了，不要因为一时找不到回执就重投。
